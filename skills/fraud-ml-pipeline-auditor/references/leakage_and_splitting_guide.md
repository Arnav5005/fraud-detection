# Data Leakage & Splitting Guide for Imbalanced Fraud Detection

Data leakage is the single most common failure mode in credit card fraud detection pipelines. Because fraud accounts for only ~0.17% of transactions, subtle information leaks cause drastic over-optimistic evaluation metrics that fail catastrophically in production.

---

## 1. Golden Rules of Splitting & Isolation

1. **Split First, Transform Later**: Never calculate statistics (mean, std, min, max, quantiles) across the entire dataset before partitioning.
2. **Stratification is Mandatory**: Always use stratified splits on `Class` so that every split reflects the true positive rate (~0.17%). Random unstratified splits on tiny positive populations can leave a partition with virtually no fraud cases.
3. **Resampling Only on Train**: SMOTE, ADASYN, and RandomUnderSampler create synthetic patterns or alter the prior probability distribution. They must run **exclusively** on the training partition.
4. **Validation Set for Optimization**: All hyperparameter choices, feature selection decisions, and probability thresholds must be chosen on the validation set.
5. **Untouched Test Set**: The test set is a release gate simulating unseen production traffic. It must never participate in model selection or threshold tuning.

---

## 2. Common Leakage Anti-Patterns & Fixes

### Anti-Pattern 1: Fitting Scalers Globally Before Splitting

```python
# ❌ INCORRECT (Data Leakage)
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X) # Leaks test statistics into training
X_train, X_test, y_train, y_test = train_test_split(X_scaled, y, stratify=y)
```

```python
# ✅ CORRECT
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, stratify=y, random_state=42)
X_train, X_val, y_train, y_val = train_test_split(X_train, y_train, test_size=0.2, stratify=y_train, random_state=42)

scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train) # Fit ONLY on train
X_val_scaled = scaler.transform(X_val)         # Transform only
X_test_scaled = scaler.transform(X_test)       # Transform only
```

---

### Anti-Pattern 2: Applying SMOTE to the Entire Dataset

When SMOTE is applied globally:
1. Synthetic fraud examples are generated by interpolating between real fraud cases in the training set and real fraud cases in the test set.
2. The test set's class distribution is artificially inflated from 0.17% to 50%, completely invalidating test metrics like Precision and False Positive Rate.

```python
# ❌ INCORRECT (Catastrophic Leakage)
smote = SMOTE(random_state=42)
X_res, y_res = smote.fit_resample(X, y)
X_train, X_test, y_train, y_test = train_test_split(X_res, y_res, stratify=y_res)
```

```python
# ✅ CORRECT
# 1. Split first
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, stratify=y, random_state=42)

# 2. Resample ONLY training data
smote = SMOTE(random_state=42)
X_train_res, y_train_res = smote.fit_resample(X_train_scaled, y_train)

# 3. Validation and Test splits remain completely untouched
# y_test still has ~0.17% fraud prevalence!
```

### Anti-Pattern 3: Tuning Classification Threshold on the Test Set

```python
# ❌ INCORRECT (Overfitting to Test Evaluation)
test_probs = model.predict_proba(X_test)[:, 1]
# Sweeping thresholds on test labels to find the best F1
best_thresh = [t for t in thresholds if f1_score(y_test, test_probs >= t) == max_f1]
```

```python
# ✅ CORRECT
# 1. Optimize threshold on validation predictions
val_probs = model.predict_proba(X_val)[:, 1]
best_thresh = select_best_threshold(y_val, val_probs)

# 2. Evaluate ONCE on test predictions using the selected threshold
test_probs = model.predict_proba(X_test)[:, 1]
final_metrics = evaluate_metrics(y_test, test_probs >= best_thresh)
```

## 3. Recommended Splitting Schema

For the Kaggle credit card dataset (284,807 rows):

| Partition | Proportion | Total Rows | Fraud Cases (Approx.) | Purpose |
|---|---|---|---|---|
| **Train** | 64% | ~182,276 | ~315 (0.17%) | Fit scaler, apply SMOTE, fit models |
| **Validation** | 16% | ~45,569 | ~79 (0.17%) | Compare models, tune threshold, optimize hyperparameters |
| **Test** | 20% | ~56,962 | ~98 (0.17%) | Final unbiased performance assessment |
